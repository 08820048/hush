# Hush 需求文档(PRD)

> 版本:v0.1(草案)  ·  日期:2026-11-23  ·  平台:macOS  ·  许可证:GPL-3.0-or-later(开源)

---

## 1. 背景与问题

我们每天注册各种产品、改 Wi-Fi、开数据库、建测试账号,都要"想一个密码"。现状通常是这样:

- **自己想**:容易重复使用、规律明显(`Name@2026`),不安全。
- **浏览器/系统自带生成**:只在网页注册表单里出现;在 App、终端、配置文件、路由器后台等场景用不了,规则也不能调。
- **密码管理器自带生成**:要先打开一个很重的应用、解锁、找到生成器入口,步骤多;很多人并不想为"生成一个密码"引入整套管理器。
- **网上的在线生成器**:密码在别人的网页里生成,不可信。

**机会点**:做一个"随叫随到、生成即走、完全离线、开源可审计"的 Mac 原生密码生成器。它只做一件事,并把这件事做到最快、最好看。

## 2. 产品定位

**一句话**:Hush 是 Mac 上最快的密码生成器——按一下快捷键,一个强密码就悄悄躺在你的剪贴板里。

**产品名寓意**:Hush = "嘘——"。密码是秘密,应该被安静地生成、安静地交付、安静地消失。

**Hush 是什么**
- 一个常驻菜单栏、可用全局快捷键唤起的轻量生成器。
- 完全本地运行、不联网、不存储、开源可审计。

**Hush 不是什么(明确不做)**
- 不是密码管理器:不保存、不同步、不自动填充账号密码库。
- 不做账号体系、云服务、付费墙。

## 3. 目标用户与场景

| 用户 | 典型场景 | 核心诉求 |
|---|---|---|
| 普通用户 | 注册新 App、改银行卡交易密码、设置 Wi-Fi | 快、不用想、好输入 |
| 开发者 / 运维 | 数据库密码、API Secret、`.env`、测试账号 | 规则可控、命令行可用、可批量 |
| 注重隐私的人 | 不信任在线生成器 | 离线、开源、无痕 |
| 需要"念给别人听/手动输入"的人 | 电视、路由器、给家人设密码 | 易读、易记、无歧义字符、大字展示 |

**关键场景(用户故事)**

1. **S1 极速生成**:我在任意 App 里正在填注册表单,按 `⌥⌘P`,面板弹出,密码已生成;按回车,复制并关闭面板,`⌘V` 粘贴即可。全程 < 2 秒。
2. **S2 一键直贴**:按 `⌘↩`,Hush 关闭并直接把密码粘贴到我刚才的输入框里。
3. **S3 适配奇葩规则**:某网站要求"8–16 位、必须含大小写和数字、不能有特殊符号",我在面板里两下调好,或直接选一个预设。
4. **S4 好记的密码**:我要设一个电脑开机密码,需要能记住——切到"短语"模式,得到 `velvet-otter-ample-crane-7`。
5. **S5 在另一台设备上输入**:我要在电视上输入 Wi-Fi 密码——按 `⌘L` 大字显示,按字符分组,一眼看清;或按 `⌘K` 显示二维码让手机扫。
6. **S6 命令行**:`hush -l 32 --no-symbols | pbcopy`,或在脚本里 `DB_PASS=$(hush)`。
7. **S7 自动化**:在"快捷指令"里调用 Hush 的"生成密码"动作。

## 4. 设计理念

### 4.1 视觉方向:沉稳、高级、克制(v2)

> 设计稿:doop 画布「Hush · Mac 设计稿 v2 · Glass」。v1(雪夜琥珀 + 声波)已被否决,不再采用。

- **图标**:全部使用项目内 `icons/glass` 的 Glass 图标(钴蓝实体 + 磨砂白玻璃),它们是界面里唯一的"装饰"。模式、预设、菜单、设置、引导都配对应图标;未选中的模式图标去饱和、降低不透明度。
- **配色**:中性色走"瓷灰"(浅色,默认)/"石墨"(深色);**唯一强调色是图标本身的钴蓝**(浅 `#1F63DA` / 深 `#3A80F0`)。警示色只在"很弱"时出现。
- **密码字符**:字母用主文字色,数字用钴蓝,符号用次要灰——能区分,但不花哨。
- **强度**:4 格细线分段条 + 文字等级与 bits;达到"极强"时显示盾牌 Glass 图标。分级:< 40 很弱(1 格,警示色)、40–80 一般(2 格,灰)、80–100 强(3 格,钴蓝)、≥ 100 极强(4 格,钴蓝)。
- **品牌**:三个渐弱的点 = 一声"嘘"。App 图标为石墨圆角方底,第一个点是钴蓝实体,后两个是磨砂白玻璃,与 Glass 图标语言一致;菜单栏图标为单色模板图。

### 4.2 其它设计原则

1. **零步骤默认**:打开即有结果。默认配置就是一个足够强的密码(随机 20 位),用户大多数时候只需按回车。
2. **键盘优先**:所有操作都有快捷键,鼠标只是备选。
3. **隐身**:不在 Dock 出现;面板不抢焦点(非激活浮动面板),用完即消失;剪贴板到时自动清空。
4. **好读**:密码等宽字体显示,数字/符号/字母用不同色调区分,易混淆字符可一键排除。
5. **原生质感**:遵循 macOS 设计语言(材质、动效、深浅色、辅助功能),不做"网页套壳"。

### 4.3 有趣的细节(微交互)

- **"耳语"出场动画**:密码出现时,字符先快速乱码滚动,再从左到右依次"安静下来"定格(约 300ms,可在设置中关闭,遵循系统"减少动态效果")。
- **单字符重摇**:鼠标点击某一个字符,只重新随机这一位(例如不喜欢某个符号)。
- **滚轮调长度**:鼠标悬停在密码上滚动滚轮/触控板,直接增减长度。
- **拖拽交付**:把密码直接拖到任意输入框或文本编辑器里。
- **菜单栏图标**:一个极简的"嘘"符号(三个点渐弱 `• • ·`);左键单击 = 直接用默认配置生成并复制(图标轻轻闪一下表示已复制),右键 = 菜单。
- **清空提示**:剪贴板持有期间,菜单栏图标末点变为空心;清空后恢复,不打扰、但让人放心。

## 7. 生成算法与安全要求

这是产品的生命线,必须严格执行并在仓库中写明。

1. **随机源**:只使用 `SecRandomCopyBytes`(系统 CSPRNG),禁止使用任何自定义或可设种子的伪随机数生成器;核心层统一封装为 `SecureRandom`,便于审计和测试注入。
2. **无偏采样**:从字符集取值时使用**拒绝采样**,杜绝取模偏差(modulo bias)。
3. **"每类至少一个"**:采用"整串重新生成直到满足条件"的方式,而不是"强行在固定位置插入",以保证均匀分布、不降低熵。
4. **熵计算**:
   - 随机:`length × log2(字符集大小)`;
   - 短语:`单词数 × log2(词库大小)`(+ 附加数字/大小写的熵);
   - 可读模式按实际音节组合空间计算,不得虚标。
   - UI 展示强度分级:< 40 bits 很弱;40–80 一般;80–100 强;≥ 100 极强(与 4 格强度条对应)。
   - 破解时间按 10¹² 次/秒(离线高速攻击)估算,并标注假设。
5. **内存**:密码不写日志、不写磁盘、不进入崩溃报告;面板关闭后尽快释放引用。(Swift 字符串无法保证安全擦除,在安全说明中如实披露。)
6. **网络**:App 不申请网络权限(Sandbox 中不开启 `com.apple.security.network.client`),从机制上保证不外传。无统计、无埋点、无崩溃上报。
7. **沙盒与签名**:启用 App Sandbox + Hardened Runtime;Developer ID 签名并经 Apple 公证。
8. **可复现与可测试**:核心生成库 100% 单元测试覆盖,包含统计学测试(大样本卡方检验验证字符分布均匀)。

## 9. 技术方案(建议)

- **语言/框架**:Swift 6 + SwiftUI,面板与菜单栏部分使用 AppKit(`NSPanel` 非激活面板、`NSStatusItem`)。
- **模块划分**:
  - `HushCore`(Swift Package):随机源、各模式生成器、熵计算、预设模型、规则解析。**无 UI 依赖**,App、CLI、App Intents 共用。
  - `HushApp`:macOS App(菜单栏、面板、设置、引导)。
  - `hush-cli`:基于 `swift-argument-parser` 的命令行工具。
- **依赖(尽量少,均为宽松许可)**:
  - `KeyboardShortcuts`(MIT)— 全局快捷键录制与注册;
  - `swift-argument-parser`(Apache 2.0)— CLI;
  - 二维码使用系统 `CoreImage` 的 `CIQRCodeGenerator`,无需第三方。
- **配置存储**:`UserDefaults`(仅存设置与预设,**永不存储密码**)。
- **建议仓库结构**:

```
hush/
├── docs/                 # 需求、设计、安全说明
├── Packages/HushCore/    # 核心生成库 + 测试
├── App/                  # macOS App (Xcode 工程)
```

## 10. 开源与发布

- **许可证**:GPL-3.0-or-later(v0.2.0 及以前为 MIT)。第三方资源(EFF 词库 CC BY 3.0、password-manager-resources MIT)在 About 与 `NOTICE` 中署名。
- **托管**:GitHub。Issue 模板(Bug / 功能建议 / 网站规则反馈)、PR 模板、`CONTRIBUTING.md`、`SECURITY.md`(漏洞私下报告渠道)。
- **分发**:
  - GitHub Releases 提供已签名并公证的 `.dmg`;
  - Homebrew:`brew install --cask hush`(App)与 `brew install hush`(CLI)——注意 Homebrew 中可能已有同名包,需提前确认命名(见第 13 节);
  - 暂不上 Mac App Store(直接粘贴需要辅助功能权限,与 MAS 沙盒限制冲突;后续可出"MAS 精简版")。
- **CI**:GitHub Actions 自动跑测试;打 tag 自动构建、签名、公证、生成发布说明。
- **更新**:v1 不内置自动更新(保持零网络);在 About 中提供"前往 GitHub 查看更新",推荐用户通过 Homebrew 升级。

## 12. 成功指标

因为 Hush 坚持**不收集任何数据**,所以不使用 App 内埋点,只看公开信号:

- GitHub Star / Fork 数、Issue 与 PR 活跃度;
- Homebrew 安装量(Homebrew 公开统计)、GitHub Releases 下载量;
- 核心体验目标:从按快捷键到密码进入剪贴板 ≤ 2 秒、≤ 2 次按键。

## 13. 风险与待决问题

## 附录 A:术语

- **熵(Entropy)**:衡量密码不可预测程度的单位(bits),每增加 1 bit,破解难度翻倍。
- **CSPRNG**:密码学安全伪随机数生成器。
- **取模偏差**:用 `随机数 % n` 取值时,部分字符出现概率略高的问题,会降低实际强度。
- **非激活面板**:弹出时不夺走原 App 焦点的窗口,是"直接粘贴"能回到原输入框的前提。
